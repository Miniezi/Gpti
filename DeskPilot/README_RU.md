# DeskPilot — помощник для Windows

Рабочий прототип с исходным кодом. Windows 10/11, Python 3.11+ с tkinter и Python Launcher.

## Быстрый запуск

1. Распакуйте архив в отдельную папку.
2. Установите Python с python.org, включая tkinter и Python Launcher.
3. Запустите start.bat. Нужен интернет для установки зависимостей.
4. Введите конечный URL OpenAI-compatible API, включая /v1, и свой ключ. Для локального сервера ключ может быть пустым.
5. Нажмите «Обновить модели», выберите модель с поддержкой tools/function calling. Список запрашивается заново при каждом нажатии; веса моделей не скачиваются.
6. Для работы с изображением экрана нужна vision-модель. Можно ввести ID модели вручную.
7. Напишите задачу. Проверяйте инструмент и аргументы в каждом окне разрешения.

Для EXE запустите build.bat на Windows. Результат: dist\DeskPilot.exe. На целевом ПК для EXE Python не нужен, но нужны компиляторы для тех языков, на которых ИИ будет собирать приложения. Сам EXE здесь не собирался и не проверялся.

## Возможности

- Чат через /chat/completions, выбор моделей через /models.
- Один API-адрес за раз; при смене адреса или модели начинается новая сессия.
- Просмотр папок, чтение фрагментов UTF-8, запись с резервной копией и перемещение файлов.
- Любые разрешённые команды через argv: компиляция, тесты, запуск программ. PowerShell можно вызвать явно. Удаление также возможно через явно разрешённую команду.
- Снимок основного монитора, мышь, нажатия клавиш, вставка Unicode через буфер обмена.
- Каждая операция, включая чтение и отправку снимка, требует отдельного разрешения. Постоянного неограниченного разрешения нет.
- Права текущего пользователя. Программа не повышает права и не обходит UAC. run не является песочницей: разрешённая команда может читать и менять любые доступные ей файлы, обращаться к сети и запускать другие процессы. Проверяйте весь код команды.
- Ключ хранится в памяти; кнопка сохранения использует системное хранилище keyring. URL и модель сохраняются в %APPDATA%\DeskPilot\settings.json; переписка на диск не пишется.

## Длинные задачи и экономия

Искусственного общего лимита числа запросов и общего числа токенов нет. Действуют контекстное окно, тариф, квоты и лимиты провайдера. При finish_reason=length программа просит продолжить ответ. Это дополнительные оплачиваемые запросы.

По умолчанию ответ ограничен 2048 токенами на запрос; значение меняется в интерфейсе. Некоторые API требуют max_completion_tokens вместо max_tokens или другой формат tools — такие провайдеры потребуют адаптера core.py. Нативные Anthropic/Gemini API напрямую не поддерживаются; нужен совместимый шлюз.

Контекст ограничивается приблизительно по символам. Старые завершённые ходы исключаются, исходная задача сохраняется; автоматического смыслового пересказа нет. Активный ход при размере более двух окон ставится на паузу: уточните текущую цель следующим сообщением. Это ограничение памяти, а не обещание бесконечного контекста. Старые снимки исключаются при новом снимке и после завершения хода. Изображения расходуют токены отдельно. Ответы инструментов ограничены по размеру.

Выберите дешёвую модель у своего провайдера; цена не определяется автоматически. Счётчик показывает total_tokens из ответов API, без денежной оценки. Общего денежного предохранителя нет: следите за расходом в кабинете провайдера. Не оставляйте зациклившуюся задачу без наблюдения.

## Остановка и ограничения

Кнопка СТОП или глобальное Ctrl+Shift+F12, если горячая клавиша зарегистрирована. Для GUI также переместите мышь в угол основного экрана — работает стандартный fail-safe PyAutoGUI. После разрешения GUI-действия есть 2 секунды на выбор нужного окна.

Стоп отменяет новые действия и останавливает запущенное дерево команды. Уже выполненные действия не откатываются. Отделившиеся процессы могут пережить остановку. Текущий HTTP-запрос может ждать до 120 секунд; списание за уже отправленный запрос отменить нельзя. Закрытие окна ждёт завершения остановки операции.

GUI работает с основным монитором и активным рабочим столом; защищённый экран UAC не поддерживается. Вставка текста заменяет буфер обмена. Резервные копии создаются только прямым write_file, а не командами и GUI-действиями. Изменения других программ между разрешением и действием не блокируются.

Содержимое разрешённых файлов и снимки отправляются выбранному API. Программа доверяет выбранному вами адресу, не устанавливает автоматически безопасность провайдера. Не одобряйте отправку секретов.

## Проверка

В папке проекта: python -m unittest discover -s tests -v

В среде Linux пройдены 7 проверок: отказ без записи, резервная копия и чтение, остановка до разрешения, завершение процесса, политика URL, цикл инструментов с mock API, учёт размера изображений. Синтаксис app.py и core.py проверен. Реальные API, Windows GUI, глобальная горячая клавиша, keyring и EXE требуют проверки на Windows. Это прототип, не готовый к промышленной эксплуатации продукт.
